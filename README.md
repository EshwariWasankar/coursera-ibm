# Coursera IBM CI/CD Final Project

This repository contains a small Flask service and CI/CD examples for the
Coursera IBM Final Project submission. The service listens on port `8000` and
returns `SERVICERUNNING`.

## Project contents

- `.github/workflows/workflow.yml` runs Flake8 and the Nose unit tests.
- `.tekton/tasks.yml` defines cleanup, clone, lint, test, build, and deploy tasks.
- `.tekton/pipeline.yml` connects those tasks into an OpenShift pipeline.
- `openshift/pvc.yaml` requests a 1Gi workspace using the
  `skills-network-learner` storage class.
- `openshift/deployment.yaml` defines the application deployment and service.

## Run locally

```shell
python -m pip install -r requirements.txt
python app.py
```

Open `http://localhost:8000/`. Run the same checks as CI with:

```shell
python -m pip install -r requirements-dev.txt
flake8 .
nosetests
```

## Run the OpenShift pipeline

The pipeline requires an OpenShift cluster with Tekton installed, permission to
create a PVC and application resources, a registry that the cluster can push to
and pull from, and a service account configured with registry credentials.

1. Apply `openshift/pvc.yaml` in the project/namespace used for the pipeline.
2. Apply `.tekton/tasks.yml` and `.tekton/pipeline.yml`.
3. Start a PipelineRun from `openshift/pipelinerun.yaml`, replacing
   `REPLACE_WITH_REGISTRY_IMAGE` with an image reference writable by the
   pipeline service account (for example, an approved OpenShift internal
   registry image).
4. Verify the PipelineRun succeeds and the application rollout is healthy.

The PipelineRun uses the existing `pipeline-workspace` PVC. The OpenShift
cluster's policy determines which service account and registry configuration
must be used.

## Assignment evidence

GitHub Actions results are generated by GitHub after this repository is pushed.
For the requested `cicd-github-validate` text, copy the successful run's job
output from the Actions page into that file; do not treat a local test run as a
GitHub Actions run.

OpenShift screenshots and application logs must be captured from a real cluster
after a successful pipeline run. Follow [evidence/README.md](evidence/README.md)
for the required filenames and capture steps. No cluster screenshots or logs
are included as if they were real.
